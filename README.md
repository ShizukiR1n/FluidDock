# FluidDock

Windows 上的 macOS 风格 Dock，用 C# + `Windows.UI.Composition` 写的。

做它的起因是现有的同类软件（RocketDock / Nexus / MyDockFinder）动画质感都不行，而原因几乎是同一个：**动画跑在应用的 UI 线程上**，线程一被布局、图标加载、进程枚举阻塞就掉帧。macOS Dock 的流畅来自 Core Animation —— 动画由独立进程按刷新率求值，和应用逻辑彻底解耦。

Windows 上的等价物是 `Windows.UI.Composition`：`ExpressionAnimation` 由 DWM 合成线程求值。这条承诺是可测的，不是说说而已 —— `tools\StallTest.ps1` 会在 UI 线程上 `Thread.Sleep`，然后证明图标在 UI 线程确凿卡死期间仍在动。

目标环境：1920×1080 @ 239Hz、Windows 10 22H2 (19045)、100% 缩放。

## 构建与运行

这台机器上有两个坑，踩过了写在这里：

```powershell
# 必须用用户级 SDK。C:\Program Files\dotnet 只有运行时，没有 SDK。
& "$env:LOCALAPPDATA\Microsoft\dotnet\dotnet.exe" build src\FluidDock\FluidDock.csproj -c Release -v q --nologo
```

- **不要用 `dotnet run`** —— 会失败。用户级 dotnet 根目录有运行时 8.0 和 10.0，唯独没有 9.0.x，而项目的目标框架是 net9.0。直接跑编译出来的 .exe，它的 apphost 会通过注册表找到 `C:\Program Files\dotnet` 里的 9.0.17。
- 构建前先 `Get-Process FluidDock | Stop-Process -Force`，否则复制步骤会报 MSB3027。
- 日志只在进程退出时落盘，所以磁盘上的日志**永远是上一次运行的**。

打包：

```powershell
tools\Publish.ps1        # -> dist\FluidDock.exe，自包含单文件，约 95 MB
```

自包含是有意的：dev 构建靠注册表找到系统里的 .NET 9，那是运气不是设计。压缩和 ReadyToRun 两个开关默认都关着，理由是实测出来的，见 `tools\Publish.ps1` 头部注释和 `tools\PackagingCost.ps1` —— 简单说，压缩省 92 MB 磁盘要拿 114 MB 内存和双倍启动时间换，因为压缩过的 bundle 条目无法内存映射，只能解压到私有堆上。

托盘右键有三项：**菜单…**（设置面板）、**显示 Dock**、**退出**。双击托盘图标等同于「菜单…」。

退出只有托盘这一条路，是有意的 —— 原来还有个 `Ctrl+Alt+Q`，但它注册在 Dock 窗口上，而那个窗口的生死由 Explorer 说了算（见下），所以它在最需要它的时候恰好不能用。

同时只能跑一个实例。

## 架构上几个不能动的地方

**每个图标是两层嵌套 visual。** 外层拥有 `Offset.X`（归放大镜的 ExpressionAnimation 管），内层拥有 `Offset.Y` 和 `Scale`（归弹跳管）。`Offset` 是单个 Vector3 属性，一条表达式绑上去就整个占住了 —— 不做这个拆分，弹跳和放大镜会互相覆盖。

**衰减函数和常量只有一处定义**，同时供表达式字符串和 C# 命中测试使用。两边各写一份迟早会漂移。

**基于时间的动画必须显式释放。** `ExpressionAnimation` 是依赖追踪的，空闲时零成本；但 KeyFrame / Spring 动画不 `StopAnimation`（配合 `CompositionScopedBatch`）就会永远请求逐帧回调。`tools\IdleTest.ps1` 守着这条。

**`ImmDisableIME` 必须在第一个 `CreateWindowEx` 之前调用，而且只对主线程调用。** 放到后面它会静悄悄地什么都不做，而且没有第二个症状 —— 只有内存悄悄多出 37 MB。

这条是量出来的，而且之前的结论是错的。第一次打开设置面板要涨约 40 MB，一直记在账上算「渲染中文时载入的字体栈」。真正的账单是**输入法**：面板是故意去抢键盘焦点的（点别处就关掉，靠的就是这个），而一个窗口第一次拿到键盘焦点时，Windows 会把用户的输入法注入进程。这台机器上是搜狗，一次带进来二十个 DLL：

```
SogouTSF.ime  SogouPY.ime  SogouFlashDll64.dll  ichat_bundle64.dll
isgpet_bundle64.dll  PicFace64.dll  systembeautify_bundle64.dll
ai_voice_input_bundle64.dll  ...
```

关掉之后 94.1 MB → 53.2 MB。这个线程上没有一个能打字的地方（面板只读一个 Esc 键），所以没有任何东西需要输入法。`tools\MenuMemoryTest.ps1` 里那一列 DLL 数就是守这条的 —— 一次开面板拉进来一批 DLL 就报错。

**但传 `0xFFFFFFFF`（整个进程）是错的**，第一版就是这么写的。全进程关掉之后，系统文件对话框的文件名框也打不了中文了 —— 那是这个程序里唯一一处「打字是用户的事，不是我们能替他拒绝的」。所以现在传的是 `GetCurrentThreadId()`，只关主线程，而文件对话框改在**它自己的 STA 线程**上跑（`MenuWindow.Dialog`）：之后创建的线程不受影响，输入法照常。代价是打开一次对话框就会把那 37 MB 拉进来 —— 但也只有那一次，而且是用户主动要求的那一次。

跨线程的那部分有两个必须成立的条件：面板的 HWND 仍然作为对话框的 owner 传过去（shell 照样会把面板禁用掉，模态行为和同线程时一模一样），以及**主线程绝不能 join 那个线程** —— 跨线程 owner 会把两个输入队列绑在一起，主线程一等就是死锁。结果是通过 `Defer` 发消息回来的。`_modal` 也因此从 bool 改成了计数：对话框不再在开启它的那次 deferred 调用里跑完，这个「别关面板」的持有必须活得比那次调用长。

**桌面层的窗口区域。** Dock 沉在桌面层时是 Progman 的子窗口，而整条桌面窗口链（Progman / SHELLDLL_DefView / SysListView32）都设了 `WS_CLIPSIBLINGS | WS_CLIPCHILDREN` —— 这是量出来的，不是猜的（`tools\DesktopStyles.ps1`）。意味着这棵树里任何位置的子窗口都会占住桌面拒绝绘制的像素，往更深处 reparent 也躲不掉，`SetWindowRgn` 是唯一的杠杆。所以窗口区域在空闲时收缩到只包住静止图标，**立即扩张、延迟收缩**：UI 线程的窗口属性追不上合成线程的动画状态，放大收尾要 280ms，弹跳可以持续数秒。

**同一个窗口的 `SetWindowPos` 必须带 `SWP_NOCOPYBITS`。** 症状是壁纸错位：拖一下「图标大小」滑块，桌面上就多出一块搬了家的壁纸，而且每拖一下多一块，直到手动刷新桌面才没。

`SetWindowPos` 默认会把窗口原来的像素搬到新位置去 —— 对一个搬完自己会重画的窗口这是笔实打实的节省，对这一个是破坏。Dock 是 `WS_EX_NOREDIRECTIONBITMAP` 且是桌面的子窗口：它一个像素也不往桌面的绘制表面里写，所以它矩形范围内那些像素**就是壁纸本身**。搬窗口于是等于把一块壁纸复制到新的偏移上盖下去，而且没有任何东西会去让它失效。改图标大小和间距都会同时改变窗口的尺寸和位置，所以是最容易撞上的两个设置。

加上 `SWP_NOCOPYBITS` 之后不再复制；另外搬完还要对**旧矩形和新矩形的并集**在父窗口上 `RedrawWindow`，一来补上刚腾出来的那条带，二来把上一个版本已经糊上去的修回来。`RDW_ALLCHILDREN` 是必须的 —— 桌面的壁纸和图标不在同一个窗口里画。

**分辨率变化由托盘窗口代听。** `WM_DISPLAYCHANGE` 和 `WM_SETTINGCHANGE` 只广播给顶层窗口，而桌面层的 Dock 是桌面的子窗口，一个字都收不到。原来 Dock 自己的窗口过程里处理这两条消息，在桌面层等于没写：切到 1680×1050，WorkerW 变成 1680×1050、工作区变成 1680×1010，Dock 还在 1920×1080 算出来的 112,844–1807,1054 上 —— 中心偏了 120 px，底边压进任务栏 44 px（量出来的）。现在托盘窗口（进程里唯一一个始终存在的顶层窗口）收到 `WM_DISPLAYCHANGE`、或者 `wParam == SPI_SETWORKAREA` 的 `WM_SETTINGCHANGE`（任务栏挪动、改大小、自动隐藏），就调 `DockWindow.OnDisplayChanged`：立刻定位一次，之后每 500ms 再定位一次、共两次 —— Explorer 是在同一条广播上调整桌面窗口的，在它自己的线程上，第一次定位读到的可能还是旧桌面。不重建视觉树：100% 缩放下图标在任何分辨率上都一样大，错的只是窗口的位置。`tools\ResolutionTest.ps1` 守着这条，会真的切一次分辨率再切回来。

**Dock 区域里的像素归 Dock 自己画。** 沉在桌面层时 Dock 是桌面窗口的子窗口，而子窗口没有自己的绘制表面：它的矩形是父表面上的一个洞，父窗口永远不往里画（上面那个 `WS_CLIPCHILDREN`），`WS_EX_NOREDIRECTIONBITMAP` 对子窗口也改变不了这一点 —— 对这个窗口 `GetDC`，拿到的就是父表面，裁到我们的区域。于是这块像素里有什么，就会从图标底下透出来；而原来没有任何人写它：`WM_ERASEBKGND` 回答「擦过了」，`WM_PAINT` 交给 `DefWindowProc`，它把更新区域验证掉但一个像素也不画。像素恰好正确的时候这没事 —— 是壁纸，或者是图标层 WorkerW 当作透明的黑色。

无边框全屏的游戏打破了它。游戏盖住整屏时桌面被完全遮挡，DWM 可以丢掉桌面的表面，Win+D 回来时拿到的是一块新的、内容未初始化的表面。Explorer 把自己那份重画一遍，我们那份还是垃圾 —— 游戏的最后一帧，或者它的一片暗色 —— 形状正好是空闲区域，一个图标一块。这是量出来的：从 Dock 的 DC 往里 `FillRect` 一块绿，屏幕上就出现同样形状的绿方块；再填黑就消失。

所以 `WM_PAINT` 现在自己接管，用 `PaintDesktop` 把壁纸按它在屏幕上的位置填进去。两种桌面布局都对：直接挂在 Progman 下时父表面本身就是壁纸（`SWP_NOCOPYBITS` 那个 bug 搬走的正是它）；拆成两个 WorkerW 的布局里 —— 图标视图在一个以黑色为透明的 WorkerW 里，壁纸在它后面另一个 WorkerW 里 —— 壁纸像素和它替换掉的透明看不出区别，在这种布局上量过，差分为零。只填黑只在第二种布局里对，在第一种里是一排黑方块。

表面被换掉这件事系统不会告诉我们，所以得自己找信号重画。前台变化是一个（Alt+Tab 出游戏、游戏退出），但 **Win+D 不发前台事件** —— 它把桌面的 WorkerW 留在 `GetForegroundWindow` 的答案里，却从不为它发 `EVENT_SYSTEM_FOREGROUND`，连按四次都没有；倒是之后把窗口恢复回来的那次 Win+D 发了两个。Win+D 做的事是把每个窗口最小化，所以钩子同时听 `EVENT_SYSTEM_MINIMIZESTART / END`。每个信号重画两次：立刻一次，500ms 后再一次 —— DWM 换表面的时机和事件到达的先后没有保证，画进了正要被扔掉的那块就白画了。`tools\UnderlayTest.ps1` 守着这条。

## 设置面板

托盘 →「菜单…」。macOS 深色模式的配色，圆角卡片分组、开关、滑块、分段控件，悬停高亮用弹簧在行之间滑动，开合是缩放 + 淡入淡出。

### 两种材质

「外观 → 主题」有**深色**和**液态玻璃**两种，随时切换，切换后当场重画。

深色是烤好的半透明底 + 噪点，不关心背后是什么。液态玻璃关心，而且**没有实时模糊可用** —— 两种 backdrop brush 都在这个窗口上试过了，`CreateBackdropBrush` 采样的是同一棵合成树里它背后的东西，对一个透明窗口来说什么都没有；`CreateHostBackdropBrush` 渲染出来是纯黑。未文档化的 accent 模糊确实能用，但它模糊的是整个窗口矩形，而窗口比面板大一圈（要留投影），模糊会露成一个直角方块，用 `SetWindowRgn` 裁回去又会把投影一起裁掉。

所以背景是**在面板显示出来的前一刻，从屏幕上抓下来的**。抓完缩到 1/5、box blur 三遍、再在全分辨率上逐像素采样回来 —— 边上那十几个像素才是重点：

| | |
|---|---|
| 折射 | 边缘把背后的东西往外推最多 9px，越靠边推得越狠。这是唯一让人读出「厚度」而不是「半透明」的线索 |
| 高光 | 两条。一条在朝向光的那侧，一条更弱的在对面 —— 光穿过玻璃从远侧内壁反回来的那条。少了第二条就是个斜角按钮 |
| 边沿 | 宽的斜面之上还有一条一像素半的硬线。只有宽斜面会看着像充了气的塑料：形对了，面不对 |
| 染色 | 按背景自己的平均亮度决定浓度。面板上是白字，背后可能是一整屏白文档，固定浓度只能按最坏情况选，然后在深色背景上浓得跟深色主题没区别 |

抓下来的是**一张静止的图**，这不是妥协：面板放好之后就不动了，而且任何别的东西拿到前台它就自己关掉 —— 它在屏幕上的这段时间里，背后不可能发生变化。唯一看得出来的缝是背后正在播的动画（视频、进度条），那个会动，而这张不会。

换主题时要重新抓，可这时候面板正在屏幕上，抓下来只会是它自己。做法是**把窗口挪到屏幕外**再抓：不能用 `ShowWindow(SW_HIDE)`，那会丢激活，而这个窗口一丢激活就自我关闭。挪窗口要跟 `DwmFlush()`，否则 `SetWindowPos` 只是排了个队，抓的时候面板还在原地。

代价：每次开面板多花约 33ms（5ms → 39ms），内存多约 5MB。开面板的动画本身是 180ms，这 33ms 在它前面，看不出来。

### 开机自动启动

「常规 → 开机自动启动」，写的是 `HKCU\...\CurrentVersion\Run` 一个值。

不用启动文件夹也不用计划任务，因为三条路里只有这条是用户能在任务管理器的「启动」标签页里看见并自己关掉的 —— 一个把自己装在系统的卸载界面够不着的地方的启动器，是会被卸载的那种。

开关的状态每次都现读注册表，不往 `dock.json` 里存副本。注册表才是 Windows 真正照办的那份，配置里的副本只会是第二种说法，而且用户一在任务管理器里关掉它，就是错的那份。两个细节：

- 任务管理器关掉一项时，`Run` 里的值原封不动，只是旁边多出一条 `StartupApproved\Run` 记录。不看这条，开关就会给一个 Windows 已经不再照办的项显示「开」。判断只看首字节的最低位（02/06 是开，03/07 是关），而不是认那四个值里的某一个。
- **存进去的路径必须和当前 exe 是同一个才算「开」。** 一个指向已经被移走或删掉的副本的残留项什么都启动不了，给它显示「开」是在说假话；显示「关」既诚实又能靠显而易见的动作修好 —— 打开开关就会重写路径。副作用是开发时 `bin\Release` 和 `dist` 是两个路径，在一个里打开，另一个里读出来是关的，这是对的。

### 检查更新

「更新 → 检查更新」一行走完整个流程：点一下去 GitHub 看最新 Release，有新版本就变成「更新到 V0.7」，**下面多出一行「V0.7 更新内容」，是那个 Release 的说明**（markdown 的标题、列表、加粗标记被拆成纯文本，最多 20 行），再点一下下载、原地替换、自己重启。说明那一行是唯一一个高度由内容决定的行，而面板的高度在构建时就定死了，所以它出现或消失都走一次面板重建 —— 和应用列表增减一项是同一条路。**`config\` 一个字节都不碰**，所以 dock.json 和图标列表原样留着 —— 这是它存在的理由：以前装一个修复要重新下载、解压到新目录、把每个图标再加一遍。

替换用的是 Windows 允许的那套改名：正在运行的 exe 不能覆盖也不能删，但能改名。下载先落成 `FluidDock.exe.new`，把正在跑的改成 `FluidDock.exe.old`，新的顶上原名，启动它，然后自己退出。新进程带着 `--after-update <旧pid>` 起来，先等旧进程真的退了再去抢单实例的互斥量（不等的话会看到互斥量被占着而直接退出，桌面上一个 Dock 都不剩），然后在后台删 `.old`。删是带重试的，每秒一次、最多半分钟：第一次真实更新就把 `.old` 留下了 —— 进程被报告为已退出的那一刻，它的镜像文件还要再被占一小会儿，而一个刚改了名的 95 MB 文件也正是杀毒软件要扫的东西；等到有人去看的时候，那个文件已经能随便删了。第二步改名失败会把第一步改回去，最坏情况是原来那个版本还在跑。

下载的东西要过三关才装：大小和 Release 说的一致、Release 带了 SHA-256 的话摘要一致、开头是 `MZ` —— 一个被存成 FluidDock.exe 的 404 页面不该装进去。

Release 的资产就是 `tools\Publish.ps1` 产出的那一个自包含 exe，故意只有一个文件：`assets\tray.ico` 缺了托盘会退回到编译进 exe 的那份图标，所以没有别的要发。版本号只在 `FluidDock.csproj` 的 `<Version>` 一处，面板标题下显示的和更新器拿去比较的都是它；Release 的标签写成 `v0.6` 这种形式，标签里数字前面的字符会被去掉。**两个要一起改。**

仓库是公开的，所以什么都不用配。token 那条路留着是为了仓库万一改回私有：私有仓库的 API 和 Release 资产对没登录的人一律回 404，这时更新器会读 `config\github-token.txt`（或环境变量 `FLUIDDOCK_GITHUB_TOKEN`），一个对这个仓库有只读 contents 权限的 fine-grained token 就够；文件不存在时行里会写「仓库不可见：需要 token」。资产是通过 API 地址加 `Accept: application/octet-stream` 拿的 —— 公开私有都走这条，且只有这条路认 token；它回的重定向由代码自己跟，不把 token 转发给存储那台主机，那边收到会直接拒绝。

`tools\UpdateTest.ps1` 不碰 GitHub：本机起一个 HTTP 服务假装成 Release（标签 v9.9，资产是 `dist\FluidDock.exe`），用 `FLUIDDOCK_RELEASES_API` 把 Dock 指过去，然后真的点面板、真的下载、真的换掉 `bin\` 里那个几百 KB 的 apphost、真的重启。这台机器上有一个本地代理，环境变量里的 `NO_PROXY` 不含回环地址，脚本自己补上，否则连 127.0.0.1 都会被代理回一个 502。

### Dock 里放什么，在这里改

面板第一组就是「应用」，一行一项：缩略图、名字，以及**只在悬停时浮出**的操作 ——「图标」换一张自定义图标，「默认」还原（只有设过自定义图标的行才有它），末尾一个 `×` 移除。下面一张卡片是两个添加按钮。

| 操作 | 说明 |
|---|---|
| 添加应用或文件… | Windows 自己的文件对话框，可多选。过滤器给了 `exe / lnk / url / bat / cmd / msc / appref-ms`，但另一档是「所有文件」—— 能被 shell 打开的都行 |
| 添加文件夹… | 同一个对话框，`FOS_PICKFOLDERS` |
| 图标 | png / ico 都收；**也可以直接选另一个 exe 或 dll**，意思是「借它的图标」。选中的图片如果在程序目录里，存的是相对路径 |
| 拖动 | 按住任意一行上下拖，其他行让开，松手落位。按在「图标 / 默认 / ×」上不触发拖动，那是点击 |

**快捷方式是被解引用的**（没有传 `FOS_NODEREFERENCELINKS`）：选一个 `.lnk`，存进配置的是它指向的目标。因为 `.lnk` 自己的 shell 图标带着左下角那个箭头角标，直接用会在 Dock 里留一排箭头。

改完照例写回 `dock.json`，Dock 的文件监视器重载 —— 和滑块走的是同一条路。

三个不显眼但不能动的地方：

- **任何会改列表的操作都必须延后到指针事件之外。** 移除会触发面板重建，而重建会 `Dispose` 掉此刻正在派发这个指针事件的那个面板。所以延后这件事写在 `DockItems` 里而不是各个行里 —— 以后新写的行没有机会忘。
- **`SettingsStore.Reload()` 只在文件字节真的变了时才替换 `Config`。** 行持有的是 `DockItemConfig` 的**引用**；每次开面板都无条件重新 Load，等于让行去改一个没人会保存的列表。所以 `Reload` 返回「换没换」，换了才重建面板。
- **落位判断用的是未夹取的位置。** 拖动中的行为了画面好看被夹在卡片范围内，但用夹取后的值算目标槽位，第一格永远够不到。另外那个比较必须是 `<=`：行静止时它的中心恰好落在补位那一行的中线上，用 `<` 会在用户还没动之前就先报「下一格」。

### 加一个设置项 = 一行

面板的内容全部写在 `Menu\MenuDefinition.cs` 里，加一个设置就是往列表里加一行：

```csharp
new SliderRow("图标大小", 24f, 96f, 2f,
    () => Metrics().IconSize,
    value => Metrics().IconSize = value,
    value => $"{value:0} px"),
```

布局、命中测试、动画、保存、生效，全都不用碰。现成六种行：

| 行 | 用途 |
|---|---|
| `ToggleRow` | 开 / 关（macOS 开关，旋钮走弹簧、轨道颜色交叉淡入） |
| `SliderRow` | 区间里的一个数 |
| `SegmentRow` | 几个互斥选项（选中块在段之间滑动） |
| `ButtonRow` | 一个动作，可标红、可顺带关面板 |
| `LabelRow` | 只读 |
| `DockItemRow` | Dock 里的一项：缩略图、名字、悬停才浮出的操作 |

第七种就是在 `Menu\Rows\` 下新建一个文件实现 `MenuRow` —— 面板本身不需要知道它存在。`MenuRow` 只要求一个 `Build`，指针事件按需重写；一切绘制都走 `MenuCanvas`，所以新写的行自动继承了「描边内缩半像素」「动画必须释放」这些已经踩过的坑。

### 面板怎么把设置传给 Dock

**不传。** 面板改的是自己那份 `DockConfig`，然后写回 `dock.json`；Dock 原有的文件监视器发现改动，自己重载重建。这条路和手改配置文件是同一条 —— 所以滑块能做到的事，手写配置一定也能，两边不会长出对方没有的分支。

唯一的例外是**层级**：它决定窗口的扩展样式和是不是桌面的子窗口，这两样在 `CreateWindowEx` 时就定死了，重建视觉树改不动。所以 `ReloadConfig` 发现层级变了会走 `Recreate()` 换一个窗口。一个需要重启才生效的开关等于一个说谎的开关。

滑块**松手才写盘**。拖动过程中连续保存是正确且不可用的：Dock 每次配置变化都会重建整棵视觉树，两秒的拖动会让它重新光栅化上百次图标。

### 写这些脚本时反复踩的坑

- **`.ps1` 文件必须带 UTF-8 BOM。** Windows PowerShell 5.1 按系统 ANSI（这里是 GBK）解析脚本，中文字面量会被静默改写 —— `"退出"` 变成 `"閫€鍑?"`。阴险在于文件本身是合法 UTF-8，运行时输出也正常，只表现为"本该匹配的比较不匹配"。
- **UI Automation 看不见 shell 的这些窗口。** 它不下钻到托盘的 `ToolbarWindow32`，对弹出菜单也返回空树。托盘图标要靠直接读工具栏（`TB_GETBUTTON` + 跨进程内存读 `TRAYDATA`），菜单要靠 `MN_GETHMENU` + `GetMenuStringW`。
- **PowerShell 把 `$null` 强转成 `""`** 传给字符串 P/Invoke 参数，所以 `FindWindowW("Progman", $null)` 什么都匹配不到。这个 bug 在两个不同脚本里各犯了一次。
- **函数会把输出流上的一切当返回值。** 函数里的 `Write-Output` 会被调用方连同真正的返回值一起收走 —— 早期版本因此把一个字符串当成"找到的托盘图标"报了出来。函数内一律用 `[Console]::WriteLine`。
- **截屏的 alpha 恒为 255**，`CopyFromScreen` 出来的位图不带透明度，拿 alpha 判断图标位置等于什么都没测。饱和度阈值也不通用（它假设桌面是灰的）。可靠的做法是**与静止帧做差分**。
- **合成按键进不去系统的文件对话框。** 三条路都试过：`SendKeys.SendWait`（静默地什么都不做 —— .NET 会回退到 journal playback，Vista 起就被禁了）、往 `ComboBoxEx32 > ComboBox > Edit` 发 `SetWindowTextW`（文字确实进去了，但「打开」仍然按空文件名走）、`keybd_event` + `VkKeyScanW` 逐字符敲（先点中编辑框自己的矩形也没用，读回来还是空的）。同样的 `keybd_event` 打 FluidDock 自己的窗口是有效的（`MenuTest` 的 Esc 就靠它）。所以 `ItemsTest` 能验证对话框**弹得对**（标题、按钮文字、过滤器、面板不被它挤掉），但「选中文件之后加没加进去」那一段是人工验收的。

## Explorer 重启

Dock 是 Progman 的子窗口，所以 Explorer 一重启，Dock 窗口就被销毁 —— 进程还活着，但屏幕上什么都没有。曾经这是个死局：退出是往 Dock 窗口发 `WM_CLOSE`，热键也注册在同一个窗口上，两条路一起断，只能开任务管理器。

现在两条都不再依赖那个窗口：

| | 做法 |
|---|---|
| 退出 | 直接 `PostQuitMessage`，走托盘窗口 —— 它是独立的顶层窗口，Explorer 拿不走 |
| 重建 | 托盘窗口收到 `TaskbarCreated` 后调 `DockWindow.Recreate()` |
| 保留的东西 | Compositor、SurfaceFactory（及其 D3D 设备）、配置监视器、前台钩子。只有 HWND 和绑在它上面的 `DesktopWindowTarget` 需要换 |
| 何时认爹 | 等 `SHELLDLL_DefView` 出现再 `SetParent`，每 500ms 试一次，最多 10 秒 |

最后一条不是保险起见。`TaskbarCreated` 是在 Explorer 还没装配完时广播的，那时 Progman 可能已经在了而图标视图还没有；此刻 reparent 进去，图标视图随后创建并落在 z-order 顶上，结果是一个**画得出来但点不动**的 Dock。等视图出现就不会落到那个位置。等待期间 Dock 是普通窗口 —— 在屏幕上、能用，只是没沉进桌面。

`WM_DESTROY` 因此**不再** `PostQuitMessage`：这个窗口的死不等于程序的死。

## 已知限制

- 静止时图标之间那 14px 的间隙在窗口区域之外，光标正好从间隙进入时要碰到图标才会触发放大。
- 弹跳期间区域完全打开，此刻恰好在拖框选会看到空洞。
- 启动弹跳大部分时候被拉起的应用窗口盖住了。
- 面板是按 100% 缩放画的，文字光栅化在 96 DPI。换到缩放显示器上会糊。
- 主线程的输入法在启动时就关掉了（`ImmDisableIME`，见上）。文件对话框跑在自己的线程上所以不受影响，但那也意味着**打开过一次文件对话框之后，那 37 MB 就回来了**，关掉对话框也不会还。
- 托盘图标默认进溢出区（任务栏的「^」里），需要手动拖到任务栏上才常驻。这是 Win10 对新注册图标的默认行为。
